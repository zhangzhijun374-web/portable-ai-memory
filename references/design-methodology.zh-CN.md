# Portable AI Memory：设计方法论

本文记录本项目背后的整理方法。它不是某一个用户的个人档案，而是一套可复用的记忆整理流程。

## 1. 为什么不能直接把聊天记录全部保存下来？

聊天记录通常混合了很多不同类型的信息：

- 长期稳定的信息；
- 一次性问题；
- 项目背景和数据；
- 尚未采纳的想法；
- 已经被新方案替代的旧决定；
- 临时任务和短期状态；
- 个人或第三方敏感信息。

如果不分类就全部保存，会产生三个问题：

1. 噪声太多：真正重要的信息被大量临时内容淹没。
2. 时间混乱：旧结论容易被误认为当前状态。
3. 隐私风险：不必要的个人信息和凭证可能被重复保存、迁移甚至公开。

因此，本项目的目标不是“保存更多”，而是“提取更有长期价值的信息”。

## 2. 记忆整理的总体流程

```text
资料来源
  ↓
来源盘点与范围确认
  ↓
原子化信息提取
  ↓
分类、去重与关系整理
  ↓
来源和可信度标注
  ↓
隐私与敏感信息审查
  ↓
建立模块化记忆档案
  ↓
用户检查与确认
  ↓
质量验证、版本记录和备份
  ↓
跨平台迁移与持续更新
```

### 第一步：资料来源盘点

先明确 AI 实际能够读取什么：

- 当前对话；
- 用户上传的文件；
- 用户提供的聊天记录导出；
- 已授权连接的数据源；
- 用户明确指定的历史项目资料。

不能把“用户有历史聊天记录”理解成“AI 已经访问了全部历史聊天”。

每个来源都应标明完整阅读、部分阅读、仅有摘要或尚未阅读。

### 第二步：原子化信息提取

将一段长对话拆分为可以独立理解的信息单元。

例如：

原始表达：

> 我最近在做一个炼油厂碳排放项目，之前有 67 家炼厂的数据，后来又补了历史年份，希望用机器学习分析驱动因素。

可以提取为：

- 研究对象：中国炼油厂。
- 分析单元：单个炼油厂。
- 已知企业规模：约 67 家。
- 数据范围：包含 2019–2021 短面板及 2000–2021 历史长面板（需要核对具体文件）。
- 研究任务：碳排放驱动因素分析。
- 候选方法：机器学习。
- 当前进度：待核实。

原子化的好处是，未来更新某一项时不必重写整个项目背景。

### 第三步：分类

推荐至少分成以下类别：

| 类别 | 保存什么 |
|---|---|
| 个人背景 | 长期有用的学习、工作和研究背景 |
| 长期偏好 | 沟通、写作、分析和交付偏好 |
| 项目档案 | 研究目标、数据、变量、方法和结果 |
| 决策记录 | 已经确定的方案及理由 |
| 工作流程 | 可以重复使用的方法 |
| 质量约束 | 不允许违反的研究或交付规则 |
| 当前状态 | 进度、阻塞、下一步 |
| 历史记录 | 已经被替代但仍有参考价值的信息 |

不要把所有内容塞进一份个人简介。

### 第四步：来源和可信度标注

重要信息要能回答：

- 这条信息来自哪里？
- 是用户明确说的，还是 AI 推断的？
- 对应哪个时间和版本？
- 是否经过原始文件核对？
- 当前是否仍然有效？

推荐标签：

- `confirmed`：已确认；
- `current_plan`：当前计划；
- `needs_verification`：待核实；
- `historical`：历史信息；
- `superseded`：已被替代；
- `inferred`：推断信息。

### 第五步：冲突处理

例如：

- 旧对话记录样本量为 120；
- 最新原始数据报告显示样本量为 116。

不能简单把两个数字拼在一起，也不能静默删除旧值。

应记录：

- 当前值：116；
- 历史值：120；
- 采用依据：最新原始数据报告；
- 旧值状态：superseded；
- 核验日期和来源。

如果无法确定哪一个正确，则保留冲突并标记待核实。

### 第六步：隐私审查

在生成文件前，检查：

- 密码、API Key、令牌和私钥；
- 账号、证件和精确地址；
- 健康、财务、法律等敏感信息；
- 第三方个人资料；
- 不应公开的研究数据和未发表文件。

公开 GitHub 仓库只应包含可复用的 Skill、模板、文档和虚构示例，不应包含用户实际的私人记忆档案。

### 第七步：模块化生成

推荐分为：

1. 核心个人档案；
2. 长期协作偏好；
3. 每个重要项目的独立档案；
4. 工作流程和质量规则；
5. 决策日志；
6. 当前项目状态；
7. 来源登记；
8. 更新日志；
9. 迁移说明。

并非每个人都需要所有文件。按实际信息创建，避免空目录和过度拆分。

### 第八步：持续更新

更新时不要重新生成全部内容，而应：

1. 找到受影响的文件；
2. 对照已有内容；
3. 判断是新增、修正、冲突还是替代；
4. 更新最小必要范围；
5. 保留重要历史决策；
6. 更新来源和版本日志；
7. 重新检查隐私与结构。

## 3. 为什么使用 Markdown？

- 人类可读；
- 大多数 AI 工具能够读取；
- 可以用 Git 管理版本；
- 不依赖单一数据库；
- 容易转换为 PDF、DOCX、JSON 等格式；
- 用户可以直接编辑，不需要特定软件。

Markdown 是默认存储格式，但并不意味着未来只能使用 Markdown。

## 4. 为什么要保留来源登记？

没有来源的记忆容易变成无法核实的“AI 说过的话”。

来源登记可以帮助新 AI 判断：

- 哪些内容来自原始文件；
- 哪些内容来自用户的直接说明；
- 哪些内容只是历史摘要；
- 哪些文件只读了一部分；
- 哪些结论需要重新验证。

这对科研、法律、医疗、财务和专业工作尤其重要。

## 5. 最终目标

用户应该能够：

- 在不同 AI 平台之间携带自己的上下文；
- 检查和修改每一条重要记忆；
- 知道信息来自哪里；
- 知道哪些信息已经过期；
- 自己备份、删除和选择性分享；
- 不依赖某一家 AI 服务商的内部记忆机制。

Portable AI Memory 的核心不是让 AI 永远记住一切，而是让用户能够管理自己真正希望长期保留的知识。
